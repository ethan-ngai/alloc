# Implementation progress

The stage definitions and acceptance gates are in [delivery and validation](08-delivery-and-validation.md), and lettered task dependencies are in [parallel workstreams](12-parallel-workstreams.md). This file records implementation state, not design intent.

The planning baseline contains documentation and the standalone POC. Task 1A adds the independently runnable `packages/contracts` package, 2A adds company fixtures, 2C adds the frontend mock API, and 1B adds the local TypeScript runtime, the owned MongoDB test harness, and the root workspace commands. Task 3B adds the transactional financial core and 5B adds the simulated action executor; scheduling, the local agent, forecasts, and UI wiring remain unimplemented. Unverified application files drafted in the original planning workspace remain excluded. Live task ownership/status is maintained through the [issue map](13-issue-map.md).

| 5. Durable runtime | 5A implemented in [#25](https://github.com/ethan-ngai/alloc/pull/25); 5B implemented in [#35](https://github.com/ethan-ngai/alloc/pull/35) | `packages/scheduler` implements contract-validated P0/P1/P2 admission, bounded fairness and per-principal limits, lease claim/renew/release with monotonic generations, retry and checkpoint transitions, and final-generation coalescing. `MongoSchedulerRepository` persists jobs with revision compare-and-swap so a displaced worker cannot advance a job it no longer owns. Verified with Node.js `v25.9.0`, npm `11.12.1`, Docker `29.7.2`, MongoDB `8.2.4`: `npm run test --workspace @alloc/scheduler` (28 unit tests) and `npm run test:integration --workspace @alloc/scheduler` (6 tests on an owned replica set) covering concurrent multi-worker claims admitting each job exactly once, expired-lease recovery fencing the displaced worker's write, a parked background job resuming from its checkpoint after an urgent P0 is admitted ahead of it, durable state surviving a simulated process restart, payload-conflict rejection, and deadline expiry clearing leases; `npm run verify` passes end to end. No model or hardware pass. Note: the pinned `mongo:8.0.30` test image cannot start on Linux kernel 6.19+ ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912)), which covers current Docker Desktop VMs, so the harness default moved to `mongo:8.2.4` with an `ALLOC_MONGO_IMAGE` override. `apps/api/src/execution`: a local simulated spending provider with an explicit one-operation-per-idempotency-key contract and controllable failure modes (`none`, `decline`, `timeout_after_apply`, `timeout_without_apply`, `unavailable_before_send`), and an executor that claims a `financial_action_intent` by revision compare-and-swap, delivers it, and persists an immutable `ActionReceipt` in `financial_action_receipts` (unique per provider operation) inside one transaction with the intent transition and an audit entry. A bounded dispatch/reconcile pass and the `npm run executor` worker entrypoint drive it; `EXECUTOR_FAULT=crash_after_provider_apply` with `EXECUTOR_FAULT_TARGET=<actionIntentId>` kills the process after the provider applied that one intent, which is how the restart gate is driven without a solvable crash loop. Rules verified: a duplicate or replayed dispatch converges on the single recorded provider operation, a `dispatching` intent left by a crash is recovered by re-delivering the same key, `outcome_unknown` is never retried blind and settles only from a provider ledger lookup (or returns to `pending` when the provider proves nothing was recorded), and a declined delivery records a failed receipt without releasing the reservation. Real replica-set and process gates verified with Node.js `v22.22.3`, npm `10.9.8`: `npm run test:integration --workspace @alloc/api -- --run test/integration/execution.integration.test.ts` (9 tests, isolated `mongo:8.0.30`, including collection-validator rejection) and `npm run test:e2e --workspace @alloc/api -- --run test/e2e/execution.e2e.test.ts` (3 tests: approve→dispatch→injected crash→restart→one reconciled action; ambiguous timeout reconciled without a second delivery; undelivered intent retried). **Unverified:** wiring 5B's dispatch onto the 5A scheduler's leases (the poller here remains a labelled interim driver until they are integrated), and no live provider, model, or hardware pass. Commitment release after a definite provider failure is deliberately out of scope: the reservation stays outstanding for the financial core. |
